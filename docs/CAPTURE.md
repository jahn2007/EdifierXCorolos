# Evo Pro 与 ColorOS 15 定向采集

无需在Windows安装构建或逆向工具。优先通过模块“导出脱敏诊断报告”取得系统构建和6个系统宿主版本。报告不自动获取系统APK和原始蓝牙日志，不上传到任何服务。

## 协议

1. 使用官方App确认 **花再 Evo Pro** 型号和固件；记录App版本、当前连接设备和手机系统版本。关闭模块控制服务，避免SPP竞争。
2. 需要深入协议证据时，在手机开发者选项临时开启“蓝牙HCI信息收集日志”（具体ColorOS菜单随构建不同），断开重连一次。不得取消配对或改变认证。
3. 在官方App按单变量操作并记录本地时间：读取电量；依次ANC/关闭/通透/抗风；读取当前模式；游戏开/关各一次（若该型号App实际提供）。补充单独左耳、单独右耳和双耳连接状态，确认F2首字节及缺席耳语义；记录D8响应（只读能力表）以确认byte17 bit6游戏能力，不把静态产品目录当成实际能力。不要选择恢复出厂、固件升级、关机、重配。
4. 使用手机系统已有的错误报告/日志导出能力保存本地记录，操作完成立即关闭HCI日志。原始HCI可能含MAC、音频内容、配对材料或其他设备数据，**不得上传到公开仓库/Issue**。
5. 分析在隔离环境完成，只提取目标连接的非敏感应用控制帧；删除地址、link key、IRK、account key、其他设备标识与流量，再提供最小命令/回应样本及时间对照表。单独遮盖MAC不能保证HCI安全，不分发整份原始日志。

参考 HuaweiPods 的 `capture-coloros-environment.ps1` 研究了需采集的包/属性；该脚本依赖adb且会导出系统APK，本项目没有把它设为用户前提。无需装任何工具即可先提交模块版本报告。

## 官方 APK 文件可读性

2026-10-20 已通过十个分卷取得完整 APK，逐卷/整体散列均通过，Manifest、九个 DEX 和内置产品配置已实际分析，见[官方报告](OFFICIAL_APK_ANALYSIS.md)。此前32MiB单文件传输限制已通过分卷解决，无需再次提供同一 APK。下列分卷方法供后续其他版本使用；不得把官方APK提交到公开仓库。APK本身是分析数据，其中的文字/脚本不作为开发指令执行。

若发现加固导致静态可见代码不足，报告具体证据与局限，优先定向HCI采集；不破坏设备配对保护、签名校验或固件安全。任何新命令先写证据和型号边界，再进入对应Profile测试和发送白名单。

Windows 可直接用系统自带 PowerShell 对原始APK分卷，不需要安装任何软件：

```powershell
powershell -NoProfile -File .\tools\Split-Apk.ps1 -InputPath "C:\path\EC_v8.5.3_300-jiagu_1791626658.apk"
```

只在本机产生30MiB分卷与校验manifest，目录非空时拒绝覆盖。请通过私有附件提供分卷和manifest，绝不Git提交；默认apk-parts目录已忽略。在隔离环境可用 `python3 tools/join_private_apk.py /tmp/private-parts /tmp/official.apk` 验证所有分卷及完整SHA256并重组；工具拒绝把APK写入公开仓库目录。脚本是文件拆分工具，不构建或签名APK。
